# Content and visual standard

Use this standard for analytical, technical, industry-research, and investment-decision decks.

## Depth test

For every substantive slide, answer these questions before designing it:

1. What decision-relevant question does the slide answer?
2. What is the supported conclusion rather than the topic label?
3. What mechanism, causal chain, or comparison explains the conclusion?
4. Which project- or industry-specific facts, figures, benchmarks, examples, or source excerpts support it?
5. What boundary, limitation, uncertainty, or counterevidence changes interpretation?
6. What does the conclusion imply for investment, diligence, strategy, timing, or risk?
7. Which visual proves or explains the point faster than prose?

Do not force every answer into visible prose, but make sure the slide is built from this reasoning. A page containing only definitions, category names, or generic advantages fails the depth test unless its explicit purpose is introductory taxonomy.

## Domain patterns

- **Technology:** mechanism → measurable performance → maturity and scalability → bottleneck → competitive differentiation → investment relevance.
- **Product or equipment:** architecture or workflow → customer use case → quantified benefit → qualification or deployment status → replacement barrier → economics.
- **Market:** definition and scope → sizing method → assumptions → growth drivers → adoption constraints → sensitivity and source dates.
- **Competition:** comparable basis → current position → evidence → durability → likely response → consequence for returns or risk.
- **Investment recommendation:** conclusion → evidence → countercase → unresolved diligence item → effect on valuation, transaction structure, milestone, or decision.

Use exact figures when available. Attach units, period, geography, sample scope, and source date when they affect interpretation. Never invent a number to make a slide feel substantial.

## Visual standard

A visual must explain, compare, locate, quantify, or demonstrate. Decoration alone does not satisfy the visual requirement.

Preferred visual types, in order of evidentiary value:

1. Data-backed native chart or table.
2. Annotated user-supplied or authoritative product, equipment, or process image.
3. Native architecture, process, causal, timeline, or comparison diagram.
4. Generated technical or conceptual illustration clearly treated as schematic.
5. Icon only when the concept is simple and no stronger visual exists.

Technical, product, process, architecture, industry-structure, and competitive-alternative pages should normally include at least one content-bearing visual. Text-only pages remain acceptable for legal language, detailed risks, methodology, or dense conclusions when imagery would not improve understanding.

## Generated-image rules

- Generate the mechanism, environment, equipment, or conceptual scene—not the final slide.
- Avoid long labels, numbers, logos, charts, and evidence-bearing text inside the image.
- Add all labels, arrows, values, legends, and sources as native HTML and PowerPoint objects.
- Request isolated or clean-background assets when the layout needs flexible placement.
- Preserve the image as a separate replaceable object and disclose when it is schematic.
- Do not treat generated appearance, scale, configuration, or branding as factual evidence.

## Asset parity checklist

For every planned asset, record:

- stable asset ID;
- source or generation prompt;
- factual, illustrative, or schematic status;
- accepted file path and pixel dimensions;
- crop and placement;
- HTML element ID;
- PowerPoint object name when supported.

Before delivery, verify that the accepted asset renders in the standalone HTML without a network connection and appears as an independent object in the corresponding PPTX slide.

## Anti-patterns

Reject or revise slides with any of these symptoms:

- four equal cards used because the content was not synthesized;
- a large empty area where a planned image should be;
- decorative icons substituted for a mechanism, product, chart, or comparison;
- generic definitions with no evidence, maturity, bottleneck, or implication;
- a generated full-slide image with uneditable text;
- a complex image that contains distorted labels that should have been overlaid natively;
- different visuals in HTML and PPTX;
- evidence claims supported only by generated artwork.
